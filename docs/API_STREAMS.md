# Streaming interfaces (not covered by OpenAPI)

The REST API is described by FastAPI's OpenAPI schema (`/docs`, `/openapi.json`; snapshot in `frontend/openapi.snapshot.json`).
OpenAPI cannot describe the two streaming interfaces below, so this file is their contract. It is written from the code:
`backend/routes/alerts.py` (WebSocket payloads) and `backend/services/claude_service.py` (SSE). The frontend validates both with
zod in `frontend/src/lib/api/schemas.ts`; change all three together.

## 1. WebSocket `GET /api/ws/alerts`

- Server-to-client broadcast only. The server ignores anything the client sends (the frontend sends a periodic `"ping"` text
  frame only to keep intermediaries from idling the connection).
- A message is sent when `POST /api/detection-event` is processed, including events generated by `POST /api/scenarios/run` and
  `POST /api/simulate/*` (those carry `"demo": true`). Nothing is sent on a timer.
- Each frame is one JSON object with a `type` field. Clients must ignore unknown types.

### `ALERT` (one per processed detection event)

| Field | Type | Meaning |
|---|---|---|
| `type` | `"ALERT"` | |
| `id` | string (UUID) | Alert id (same as `alert_id` in the REST response and `id` in `GET /api/alerts`) |
| `camera_id`, `city`, `event_type` | string | Device, its city, detection type (`loitering`, `perimeter_breach`, `unauthorized_access`, `anomalous_motion`) |
| `trust_score` | int 0-100 | IG-DCTF final score (primary decision score) |
| `action_tier` | `"high_trust"` / `"medium_trust"` / `"low_trust"` | Tier of `trust_score` (>= 80, 50-79, < 50) |
| `contributing_factors` | string[] | Factor keys that fired |
| `corroborated_by` | string[] | Corroborating camera ids |
| `detected_at` | ISO 8601 string | Event time |
| `probabilistic_score` | int | Bayesian log-odds model score (comparison) |
| `decayed_score`, `decay_factor` | int, float | Time-decayed score and multiplier |
| `corroboration_method` | string | How corroboration was decided |
| `notification_channel`, `notification_priority` | string | Tiered dispatch routing |
| `velocity_suspicious` | bool | Camera is in a suspicious corroboration-velocity pair |
| `signal_integrity_score` | float 0-1 | Channel B signal integrity `s` |
| `drift_score` | float 0-1 | Tier 1 banner drift |
| `integrity_gate_tripped` | bool | `s < theta_low` (score capped at 30) |
| `gate_status` | `"nominal"` / `"tapered"` / `"hard_gated"` | Gate region |
| `cyber_trust_score` | int | Channel A score `T_cve` before the gate |
| `demo` | bool | `true` for simulator and scenario traffic. Also persisted as `alerts.is_demo` and returned by `GET /api/alerts` |

### `INTEGRITY_GATE_TRIPPED` (extra message, sent just before the `ALERT` when the gate trips)

| Field | Type |
|---|---|
| `type` | `"INTEGRITY_GATE_TRIPPED"` |
| `camera_id`, `city` | string |
| `drift_score`, `signal_integrity` | float |
| `gate_status` | string (`"hard_gated"`) |
| `detected_at` | ISO 8601 string |
| `action` | `"dispatch_technician_for_physical_inspection"` |

## 2. Server-Sent Events `POST /api/brief/stream`

- Request body: the `BriefRequest` model (see OpenAPI). Response: `text/event-stream`.
- Each event is a single `data: <json>` line followed by a blank line. The JSON has a `type`:

| `type` | Fields | When |
|---|---|---|
| `text` | `content: string` | Whole brief at once: a cached brief, or the notice that no language-model key is configured |
| `chunk` | `content: string` | Incremental text while the model streams |
| `done` | `risk_level: string` | End of stream (`LOW` / `MEDIUM` / `HIGH` / `CRITICAL`; `MEDIUM` when no key is configured) |
| `error` | `message: string` (at most 100 characters) | The model call failed; the stream ends |

- A non-2xx HTTP status (for example 422 for an invalid body) is an ordinary JSON error, not an SSE stream; clients must check the
  status before reading events (`frontend/src/lib/api/sse.ts` does).
